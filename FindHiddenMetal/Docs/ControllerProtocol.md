# 숨은 금속 찾기 - 컨트롤러 통신 규약 (v0.1)

PC(Unity, 터치모니터 SW) ↔ 금속탐지 장치 컨트롤러(회전 원판, 탐지목표물 LED).

## 1. 연결

| 항목 | 값 |
|---|---|
| 방식 | RS232 (USB-Serial 가능) |
| 속도 | 19200 bps, 8N1, 흐름 제어 없음 |
| 포트 | `persistentDataPath/port.json` (첫 실행 때 `StreamingAssets/port.json`을 복사) — `enabled: true`인 포트 전부. 컨트롤러 id는 구분하지 않음 (어느 포트로 들어온 메시지든 같게 처리, 명령은 열린 모든 포트로 송신) |
| 문자 | ASCII, 대문자 |
| 줄 끝 | PC → 컨트롤러: `\n` / 컨트롤러 → PC: `\n` 또는 `\r\n` |
| 구분자 | 값이 있으면 `,` (공백 없음) |

## 2. PC → 컨트롤러

| 명령 | 시점 | 컨트롤러 동작 |
|---|---|---|
| `LED_ON` | 정답 확인을 누르거나 제한 시간 종료 (정답공개) | 탐지목표물 LED 8개 전체 점등 |
| `LED_OFF` | 결과 화면을 닫거나 체험을 중단할 때 (`ROTATE` 직전) | LED 전체 소등 |
| `ROTATE` | 결과 화면 종료 / 체험 중 HOME 또는 무입력으로 중단 | 원판 90° 회전 → 끝나면 `ROT_DONE` 송신 |
| `STATE?` | SW 시작 시 1회 | 현재 회전 단계를 `STATE,n`으로 응답 |

## 3. 컨트롤러 → PC

| 메시지 | 의미 |
|---|---|
| `ROT_DONE,n` | 회전 완료. `n` = 현재 단계 0~3 (원점 센서가 있을 때) |
| `ROT_DONE` | 회전 완료. 단계를 모르면 값 생략 → PC가 저장된 단계 + 1로 계산 |
| `STATE,n` | `STATE?` 응답. 단계를 모르면 응답하지 않아도 됨 |
| `ERR,내용` | 장치 오류 (PC는 로그만 남김) |

- 회전 단계 0 = `Setting.json`의 `baseTargets` 배치. 1·2·3은 각각 90°·180°·270° 회전한 배치 (방향은 `rotateClockwise`).
- PC는 현재 단계를 `persistentDataPath/deviceState.json`에 저장해 재실행 후에도 이어간다.

## 4. 순서

```
[체험 완료]  PC → LED_ON
[결과 닫기]  PC → LED_OFF
             PC → ROTATE
             (원판 회전)
             컨트롤러 → ROT_DONE,1
             PC: 대기화면 복귀, 다음 체험 정답 = 1단계 배치
```

## 5. 예외 처리 (PC)

| 상황 | 처리 |
|---|---|
| `ROTATE` 후 `rotateTimeoutSeconds`(기본 15초) 안에 `ROT_DONE` 없음 | 회전된 것으로 보고(단계 + 1) 진행, 경고 로그 |
| 포트가 닫혀 있음 (장치 없음, `enabled: false`) | 명령 송신 생략, 회전은 1초 후 완료로 처리 → 체험 흐름은 멈추지 않음 |
| 요청하지 않은 `ROT_DONE,n` 수신 | 단계 값만 맞춤 |
| 알 수 없는 메시지 | 경고 로그 후 무시 |

## 6. 장치 쪽 확인 필요

- 레벨미터·검류계는 자석–센서 반응으로 장치 단독 동작 (PC 통신 없음).
- 원점 센서 유무 → 있으면 `ROT_DONE,n`/`STATE,n`에 단계를 실어 보내 주면 PC 단계와 어긋날 일이 없음.
- `baseTargets`(0단계 좌표 8개)는 실제 원판 제작 후 격자 위치를 확인해 `Setting.json`에 입력.
